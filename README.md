# 운동일지 × 갤럭시 워치 — Wear OS 연동 MVP

## 무엇을 만들었나

원본 `index.html`의 날짜별 운동 기록 형식을 그대로 사용하는 3개 구성요소입니다.

- `web/`: 기존 휴대폰 PWA + 워치 동기화 설정. **기존 `split3-log`, `split3-routine` 로컬 데이터 유지**
- `server/`: HTTPS로 공개해야 하는 단일 사용자 동기화 API. SQLite 저장소, 비밀 토큰 인증, 날짜별 변경 버전 검사
- `watch-app/`: Android Studio에서 여는 Wear OS Java 네이티브 프로젝트. 워치에서 세션 선택, 중량·반복 입력, 세트 저장/수정, 종목 완료, 휴식 카운트다운

기존 휴대폰 앱은 그대로 사용하고 워치와 서버를 통해 기록을 동기화합니다. 삼성헬스/심박수 연동은 이 버전 범위 밖입니다.

## 1. 서버 실행 및 배포

서버는 로컬 테스트 외에는 **공인 HTTPS** 주소로 운영해야 합니다. Render, Railway, VPS 등에서 컨테이너 배포가 가능합니다. 환경변수 예:

```bash
WORKOUT_TOKEN='여기에_무작위_긴_비밀_문자열_최소_24자'
WORKOUT_ORIGINS='https://사용자명.github.io'
WORKOUT_DB='/data/workout.db'
```

비밀 토큰 생성 예: `python -c "import secrets; print(secrets.token_urlsafe(32))"`

```bash
cd server
python -m pip install -r requirements.txt
export WORKOUT_TOKEN='...'
export WORKOUT_ORIGINS='https://사용자명.github.io'
export WORKOUT_DB='./workout.db'
uvicorn app:app --host 0.0.0.0 --port 8000
```

`http://localhost:8000/api/health`로 로컬 점검할 수 있습니다. 실사용에서는 HTTPS 리버스 프록시가 필수입니다. 서버의 `/data` 또는 SQLite 파일은 **영속 볼륨**에 보관해야 합니다. 무료 호스팅의 임시 파일 시스템에 DB를 두면 기록이 사라질 수 있습니다.

이 서버는 단일 사용자용으로, `WORKOUT_TOKEN`을 아는 모든 클라이언트가 전체 운동기록을 읽고 수정할 수 있습니다. 공개 저장소에 토큰을 올리지 마세요. 독립 계정·암호화 저장·접근 감사 등의 운영 보안은 포함되어 있지 않습니다.

## 2. 기존 휴대폰 PWA 업데이트

1. **먼저 기존 PWA의 '기록' 탭에서 JSON 백업 파일 저장.**
2. 기존 GitHub Pages 저장소에 `web/index.html`, `web/sw.js`, `web/manifest.webmanifest`, `web/icons/`를 업로드합니다. `web/` 하위 디렉터리 그대로 올리는 것이 아니라 **그 안의 파일을 사이트 루트에** 올립니다.
3. 홈 화면 앱을 재실행합니다. 기록과 루틴은 같은 브라우저 저장소에 유지됩니다. 기존 PWA를 삭제/재설치하지 마세요.
4. 앱 화면 맨 아래 `갤럭시 워치 동기화`에 서버 HTTPS 주소와 토큰을 입력합니다.
5. 최초 연결 시 기존 서버에 기록이 있으면 **서버 기록을 우선 적용**하므로 사전 백업이 중요합니다. 서버가 비어 있다면 현재 휴대폰 기록을 업로드합니다.
6. 웹앱이 실행 중이면 약 5초 간격으로 워치에서 바뀐 기록을 반영합니다. 앱이 닫혀 있으면 다시 열 때 동기화합니다.

서로 다른 기기에서 동일한 날짜를 동시에 편집하면 충돌할 수 있습니다. 날짜별 버전이 충돌하면 오류가 표시되며, 자동으로 덮어쓰지 않도록 만들었습니다. **중요한 운동 기록은 JSON으로 수시 백업하세요.**

## 3. 갤럭시 워치 앱 설치

**Apple Silicon macOS 사용자:** 먼저 `watch-app/MAC_SETUP.md`를 참고하고, 터미널에서 `bash ./setup-mac.command`를 실행하면 공식 Gradle Wrapper를 생성하고 APK 빌드를 시도합니다.

1. 최신 Android Studio에서 `watch-app/` 폴더를 엽니다.
2. Android SDK 35 및 JDK 17을 준비하고 Gradle Sync를 수행합니다. 필요 시 Android Studio가 Gradle을 내려받습니다.
3. **Run** 대상 기기를 워치 에뮬레이터 또는 개발자 옵션/무선 디버깅을 켠 실제 갤럭시 워치로 선택합니다.
4. 앱 시작 → `서버 연결 설정` → 2번에서 사용한 HTTPS URL과 토큰을 동일하게 입력합니다.
5. 당일 세션 선택 → 운동 종목 선택 → 중량·반복 횟수 입력 → `세트 저장 + 휴식 시작`.
6. 휴대폰 PWA를 다시 열어 기록을 확인합니다.

앱은 워치에서 직접 인터넷에 접속하는 방식입니다. 워치가 휴대폰과 페어링되어 있으면 통상 휴대폰의 네트워크를 사용할 수 있지만, 해당 연결이 끊어져 있거나 인터넷에 연결되지 않으면 동기화할 수 없습니다.

## 개발/검증 상태

- `server/app.py` 서버 API: 로컬 FastAPI 테스트에서 인증, 세트 저장, CORS, 버전 충돌 확인
- `web/index.html`: JavaScript 구문 검사 완료
- **워치 Java 프로젝트: 이 작업 환경에 Android SDK/Gradle 빌드 환경이 없어 APK 빌드 및 워치9 실기기 테스트는 수행하지 못했습니다.** Android Studio에서 추가 검증이 필요합니다.

## 기술적으로 유의할 점

- 워치 기록은 `days[YYYY-MM-DD].sets[exerciseId]` 구조로 저장됩니다. 휴대폰 앱 기존 스키마를 유지합니다.
- 워치 앱은 `POST /api/watch/set`으로 **해당 인덱스의 세트**를 신규 기록 또는 수정합니다.
- 종목 완료는 `checks[exerciseId]=true`로 저장합니다.
- 백그라운드 알림, 웜업/탑/드롭 태그 편집, 클라우드 계정 기반 로그인, 고급 충돌 해결은 후속 개발 항목입니다.
